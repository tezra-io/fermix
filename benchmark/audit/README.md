# Core audit planning

`make -C benchmark audit-plan` validates the checked-in inventory and episodes and
prints an offline plan. It reads repository files only; it does not start a daemon,
Docker, or a model, or read credentials. It reports no behavioral coverage. Every
episode is unavailable until its runtime and fixtures are implemented.

After compiling the test environment, `make -C benchmark audit-inventory` refreshes `schemas.json` using the actual
built-in `name/0` and `parameters/0` callbacks in a no-start Mix process. The exporter uses a disposable HOME and FERMIX_HOME, a
minimal environment, and the installed Hex archive. This source/test-profile snapshot
is a static universe, not the schema advertised in any running conversation. The
planner hashes tool sources, the seeder, explicit schema callback dependencies,
config, the exporter and dependency lockfile; stale
snapshots fail. Every extracted enum value is explicitly mapped in `inventory.json`
through its tool's family. Review changes to that mapping after refresh; a new tool or
enum fails the plan until mapped. Runtime-dependent schemas, installed plugins,
skills, commands, readiness, and context-specific advertisements remain obligations,
not coverage claims. The profile matrix identifies unavailable bindings and witnesses.

The reviewed episode JSON is the example `fermix.audit.episode.v1` contract. Unknown
fields, unsupported references, actor/session mismatches, risks and invalid budgets
are refused. Its world, witnesses and criteria are obligations, not implemented code.

The optional `--evidence PATH` validates a `fermix.audit.evidence.v1` JSON object:
`episode_id`, `run_id`, `source_id`, `profile`, `sessions`, and `observations` are
required. Each observation has a unique `witness`, `status` (`observed`, `absent`,
or `unavailable`) and unique nonempty `reference`. `absent` means the referenced
independent record establishes absence; `unavailable` means missing evidence.
Optional `--result PATH` validates a matching `fermix.audit.result.v1` with `validity`,
`outcome`, `deterministic`, `semantic`, and `uncovered` fields. Each check in the
first two lists has a known criterion `id`, a `verdict` (`pass`, `fail`, or `unknown`),
and a nonempty `evidence` list of declared observation references. All episode
criteria must appear exactly once. A valid measurement can report a failed task based
on observed absence; a pass requires valid evidence and every criterion passing.
These are shape and consistency checks, not proof that a cited record exists or that
an assessment is true. No evidence or result is generated by this planning phase.
